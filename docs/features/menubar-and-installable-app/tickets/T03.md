# T03 — 폰에서 설치 가능한 웹앱으로 만들고, 다시 묻지 않게 한다

## Goal

폰 브라우저가 이 페이지를 **홈 화면 앱으로 설치**할 수 있게 하고, 설치한 앱을 다시 열면 **번호를 묻지 않고** 스스로 연결되게 한다.

## Why this slice

캡틴이 겪은 두 증상의 나머지 절반이다.
설치 권유가 안 뜬 이유는 인증서가 아니라 **선언 자체가 없어서**였고(F20), 번호를 매번 묻는 이유의 두 번째 겹은 **QR 로 여는 것 자체가 저장된 기록을 지우기 때문**이다(F21).
설치한 앱은 아이콘으로 열리므로 해시가 없고, 그때 비로소 이미 만들어진 재연결이 작동한다(F22).

## Produces

- 웹앱 선언(manifest)과 그것이 요구하는 아이콘 크기들
- service worker
- 해시 없이 열었을 때의 자동 재연결이 **실제로 성립하는 상태**

## Consumers

`grep -n` 실제 출력으로 확인한 자리들:

**설치 선언이 붙을 자리:**
- `web/index.html:8` — `apple-mobile-web-app-capable`. 이미 있다.
- `web/index.html:10` — `theme-color`. 이미 있다. manifest 의 값과 어긋나지 않게 하라.
- `web/index.html:11` — `<title>QuicMic</title>`. manifest 의 이름과 맞춰라.
- `web/index.html:14` — `rel="icon"` 인라인 base64. 🔴 **64×64 다**(디코드해 실측). 설치에는 192·512 가 필요하다.
- `web/index.html:15` — `rel="apple-touch-icon"`, 같은 64×64 그림.
- 🔴 **`rel="manifest"` 링크가 없다**(`grep -c` = 0). 이것이 설치 권유가 안 뜬 직접 원인이다.

**자동 재연결에 걸린 자리:**
- `web/app.js:274` — `const hash = location.hash.slice(1)`.
- `web/app.js:277` — 🔴 해시가 있으면 `localStorage.removeItem('sessionToken')`. **QR 로 여는 한 저장된 기록이 지워진다.**
- `web/app.js:286~292` — 해시가 없을 때 `storedToken` 을 재사용하고 `renewSessionToken()` 을 부른다. **이미 만들어져 있다.** 설치한 앱이 이 분기를 타야 한다.
- `web/app.js:342` — `renewSessionToken()`.
- `web/app.js:362~392` — `returnToPairing(reason, serverGone)`. 🔴 `serverGone` 이면 번호 입력을 잠그고 **새로고침을 요구한다.** 그 주석이 이유를 밝힌다: 서버가 돌아오면 인증서가 새로 만들어져 고정된 해시가 어긋난다는 것. **T01 이 그 전제를 없앤다** — 이 티켓이 그 경로를 다시 판단해야 한다.

**자산이 실리는 방식:**
- `src/server/assets.rs:12~14` — `#[folder = "web/"]`. `web/` 에 파일을 더하면 바이너리에 자동으로 박힌다. 별도 배포 단계가 없다.

## Touched surfaces

- `web/index.html` — manifest 링크, 아이콘 링크
- `web/` — manifest 파일, 아이콘 파일들, service worker
- `web/app.js` — service worker 등록, `returnToPairing` 의 강제 새로고침 경로 재판단
- 위의 테스트

## Explicitly out of scope

- 메뉴바 — T02 가 소유한다. Tabler 원본은 T02 가 vendoring 한 것을 **재사용**하고 크기만 파생해라.
- 저장소 — T01 이 만든 것에 기댄다.
- 전송·오디오·짝짓기 규약 변경.
- 오프라인 동작 — service worker 는 설치 요건을 충족하는 최소한이면 된다. 캐시 전략을 설계하지 마라.
- 안드로이드 네이티브 앱(D5) — 이 티켓이 실패해야 그 조건이 열린다.

## Locked decisions

- **D4**(`grill.md`): 아이콘은 Tabler 마이크다. **T02 가 vendoring 한 같은 원본**에서 파생해라(F27 — 메뉴바와 웹앱이 어긋나면 안 된다).
- **F26**(`grill.md`): 원본이 무엇이든 192×192·512×512 를 새로 뽑아야 한다.
- **F21**(`grill.md`): QR 의 해시 형식(`main.rs:212`)을 바꾸지 마라. QR 로 처음 짝짓는 경로는 지금 그대로 옳다 — 바뀌는 것은 **설치한 앱이 해시 없이 열린다**는 사실뿐이다.
- **F30**(`grill.md`): 인증서가 유지되면 `app.js:390` 의 강제 새로고침이 존재 이유를 잃는다. **지울지 말지는 이 티켓이 판단하되, 판단 근거를 PR 에 남겨라.**

## Implementation notes

🔴 **실물로만 답할 수 있는 것이 하나 있다.**
자체 서명 인증서에서 service worker 가 등록되는지는 문서로 확정할 수 없다(F15).
안드로이드 Chrome 은 인증서를 **신뢰 저장소에 넣으면** secure context 로 인정하지만, 경고를 클릭해 넘긴 것만으로는 등록이 거부될 수 있다.

QuicMic 은 `GET /ca` 로 CA 를 이미 내려준다(F16, `src/server/api.rs:390`).
T01 이 인증서를 유지시키므로 그 신뢰 설치가 **한 번으로 끝난다** — 이 조합이 성립하는지가 이 티켓의 핵심 검증이다.

**등록이 끝내 거부되면 멈추고 `needs-decision:` 으로 보고해라.** 우회하지 마라 — 그것이 캡틴 결정 D5(안드로이드 앱)의 발동 조건이다.

- `web/app.js:274~292` — 해시 분기와 재사용 분기
- `web/app.js:362~392` — `returnToPairing` 과 강제 새로고침

## Regression guards

- `cargo test` 전체
- QR 로 처음 짝짓는 경로가 여전히 동작하는지 수동 확인

새로 져야 할 것: manifest 가 유효한지, 아이콘 크기가 요건을 만족하는지, 해시 없이 열면 재사용 분기를 타는지.

## Acceptance criteria

1. 폰 브라우저에 설치 권유가 뜬다.
2. 설치한 앱을 열면 번호를 묻지 않고 연결된다.
3. QR 로 처음 짝짓는 경로가 여전히 동작한다.
4. QuicMic 을 재시작해도 설치한 앱이 다시 연결된다(T01 과 함께 성립).
5. 아이콘이 메뉴바 것과 같은 원본에서 나왔다.
6. `cargo test` 전체 통과.

## Verification

🔴 **캡틴의 실제 안드로이드 기기로 확인해야 한다.** 로컬 테스트로는 수용기준 1·2 를 증명할 수 없다.
절차: CA 설치 → 페이지 열기 → 설치 권유 확인 → 설치 → 앱 열기 → 번호 안 묻는지 확인 → QuicMic 재시작 → 다시 열어 확인.

`cargo test` 는 그와 별도로 통과해야 한다.
전체 출력은 `/tmp` 아래에 남겨라.
